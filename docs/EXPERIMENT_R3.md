# R3 — measured bottleneck attack (experimental)

R2 Guitar Hero logs: 236 samples; 500 MHz CPU, core 3 available; 21,196 JIT blocks; median VM FPS 9.4, max game FPS 14. Warm interval 196–246 seconds: ~26 VM FPS and 13–14 game FPS; ~40% EE profile share in VU1sync. Cold start is dominated by JIT. No measured R3 gain yet.

R3 defaults: asynchronous VIF1/VU1 queue; keep PATH3 and guest-visible synchronization fences; no artificial vblank wait; bounded 100 us worker spin; IOP worker on core 1; SPU2 mixer on core 3 with core 2 fallback; retain GS batches across pumps and defer texture allocations. Known RE4 workload retains measured scheduling. JIT cache reuses serialization storage, avoids flushing for older cached records and rejects missing/failed executable fingerprints. Direct session.txt records build, game, async stats, JIT cache hits and stalls; boot-error.txt records boot exceptions. Existing diagnostics retained.

The parallel modes can affect timing, rendering and audio. To revert the new defaults use performance_mode=0 in ux0:data/VitaPS2exp/experiment.ini (put it before any explicit overrides). Independent controls: iop_thread=0, spu_core=2, vu1_async=0, vu1_vblank_sync=1, vu1_spin_us=0, pump_keep_batch=0, texture_lazy_texels=0. Use warm cache and equal scene for comparison. A new eboot invalidates old JIT cache. Do not disable PATH3 ordering fences. No arbitrary graphics omissions or forced underclock. Research references: PCSX2 Threading VU1 documentation, parallel-ps2 MTVU, VitaSX2 README; independent implementation and existing BSD project mechanisms, no GPL source copied.
