# R7 (00.15) — compatibility and expanded JIT
The user reports that Guitar Hero no longer advances the first cutscene (R4 reached gameplay; R5/R6 did not). R7 restores the R4 mixer affinity (core 2) for SLUS-21224, leaves synchronous VU1 and inline IOP, preserves clocks and NEON readback accuracy. This is an A/B recovery attempt, not a confirmed fix.
The stock 16 MiB executable VM quota is confirmed in R5. Optional already installed kubridge v0.3.1_hotfix can provide one contiguous 32 MiB executable pool using its documented reserve/commit/flush ABI. Weak VitaSDK import stubs are checked before use; if unresolved or allocation fails, use stock VM pool. No plugin bundled, installed, or kernel patches applied. Set jit_kubridge=0 to force stock allocation; jit_pool_max_mb=16 or 32. r7-jit-pool.txt reports actual backend. No hardware validation yet.
Independent optimizations: keep incremented COP0 COUNT on JIT value stack (same value, increment, sign extension, no timer skip), remove redundant branch in successful WaitSema, make existing semaphore idle heuristic configurable (sema_idle=0 disables only that heuristic). Existing ee_stay_in_slice=0, iop_stay_in_slice=0, mpeg_hle=1 and decoder affinity now available in experiment.ini. Native MPEG HLE checks recognized libmpeg signatures, not promised to support GH. Do not force timing skips or falsely report DMA completion. SIF0 stop/SMFLAG, ROMVER, SPU2 unknown register semantics, deep VU allocator and selective EE eviction remain pending. Sources: Grarak/azahar src/core/arm/vita/arm_vita_native.cpp (system tick/mutex thunks, native ARM execution), shader_jit_a32_compiler.cpp (ARM32 shader JIT), src/citra_vita/gxm_present.cpp (GXM); Franckrst/WinVita public kubridge API and D2Vita weak import ABI. No GPL source copied. PT-BR retained. r7-logs/ per session; new eboot produces a new cache.
